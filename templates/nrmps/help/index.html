Quick start

  1. Create an account and open Simulations, then New simulation. It starts with a working default configuration: 200 applicants and 10 programs with about 20 positions each.
  2. On the simulation page, adjust the configuration if you like and save it.
  3. Under Populations, create the applicants and the programs (or upload them as CSV).
  4. Under Initialize Interviews, create one row per applicant-program pair.
  5. Under Pre-Interview, compute the ratings and rankings.
  6. Open View list to browse the results, or download them as CSV.

Every destructive action asks for confirmation and says what it will delete. Recreating a population deletes the interview rows, because they belong to the old population.

How the simulation works

The residency Match pairs applicants (medical students) with residency programs. In the real process applicants apply, programs invite some of them to interview, both sides submit rank order lists, and the NRMP's algorithm produces the match. This simulator currently models the part before applications: who would prefer whom, and how accurately each side can tell.

Populations
Each applicant has a base score between 0 and 1 (overall strength) and one score per applicant attribute that programs value (for example board_scores, research). Each program has a base score (overall quality), a number of positions and one score per program attribute that applicants value (for example reputation, location). Scores are drawn from Beta distributions with the configured means and spreads; attribute scores are centred on the base score.
Preferences
Every applicant weighs the program attributes, and every program weighs the applicant attributes. The weights sum to 1. "Preference diversity" controls how much the weights differ between people: at 0 everyone weighs the attributes the same way.
True utility
An applicant's true utility for a program is the weighted sum of the program's attribute scores: U = Σ weight × attribute score, between 0 and 1. Programs value applicants the same way.
Pre-interview rating
Before interviews, each side sees the other only imperfectly: rating = U + noise, where the noise is normally distributed with the configured standard deviation. A noise of 0 means perfect information.
Rankings
Each applicant ranks every program by rating (1 = highest), and each program ranks every applicant. Ties are broken by the lower record number, so ranks are always 1, 2, 3 … with no gaps.

The interview table shows, for every pair, both true utilities, both ratings and both ranks, so you can see how much the noise changes the orderings.

Parameters

Scores and utilities are on a 0-1 scale. Parameters marked Not used yet belong to stages that are not implemented; they are saved but have no effect.

CSV files

You can upload your own applicants and programs instead of generating them. A downloaded file can be uploaded again unchanged. The whole file is checked first: if any row has a problem, nothing changes and the problems are listed with their line and column.

  • Applicants: {{ csv_columns.applicants|join:"," }} (sample file)
  • Programs: {{ csv_columns.programs|join:"," }} (sample file)
  • The first row must name the columns. name and score (and capacity for programs) are required; the others may be left out.
  • score is between 0 and 1; capacity is a whole number of positions.
  • score_meta and meta_preference are JSON objects such as {"research": 0.5, "honors": 0.8}. Attribute names use lowercase letters, digits and underscores. Attribute scores are between 0 and 1; preference weights are 0 or more.
  • To rate, every applicant's weights must use attributes every program has a score for, and the other way round. Uploaded populations without weights cannot be rated; the step says what is missing.
  • Files may be up to {{ max_upload_mb }} MB and {{ max_upload_rows|intcomma }} rows, in UTF-8 (Excel's "CSV UTF-8" works).

Please use made-up or anonymised data only (see the terms).

Current limitations

  • Only the stages up to pre-interview rankings run. Applications, preference signals, interview invitations, interviews, rank order lists and the match are being built.
  • The current generator draws preference weights that often sit at their limits, and applicants tend to agree about which programs are best. A new model with explicit correlation settings replaces it.
  • Each step runs while you wait, so markets are limited to {{ max_pairs|intcomma }} applicant × program pairs.
  • Results are simulations under the assumptions you set. They are not predictions of any real applicant's or program's match.
